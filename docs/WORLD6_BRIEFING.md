# Briefing: designing World 6 (Hallow's End) as a beta

For a new Claude Code session. Paste this as the first message, or say "read docs/WORLD6_BRIEFING.md first".

## The situation (2026-10-21)

- Gourd Guard Release 1 (worlds 1–5) is in closed testing on the App Store (TestFlight) and Google Play. **Production launches without World 6.**
- The owner wants to start designing World 6 now and play it only through the private **Claude artifact playtest link**, never in the store builds.
- The owner designs the rules. Your job is to build what they describe, keep the docs in sync and check balance with the bot. Read `CLAUDE.md` first: it has the project rules, test commands and working rules. They all still apply.

## Rule 1: World 6 must never reach the store builds

Set this up before writing any World 6 content:

1. **Own branch.** Work on a new branch `w6-hallows-end`, made from `r1-ground-rules`. The store builds are made from `r1-ground-rules` only, and World 6 work is never committed there.
   - Launch fixes happen on `r1-ground-rules` (often in another session). Merge them into `w6-hallows-end` regularly with `git merge r1-ground-rules`, so the playtest has the latest game.
   - Never merge `w6-hallows-end` into `r1-ground-rules` unless the owner says so.
2. **Safety switch.** Show World 6 only when a build-time flag is on, e.g. `VITE_W6=1` read through `import.meta.env.VITE_W6` in `src/data/worlds/index.js`. With the flag off, `WORLD_LEVELS` has five worlds and the game looks exactly like Release 1.
   - Only the playtest build turns it on: `VITE_W6=1 npm run build`.
   - The iPhone and Android builds (`npm run build`, then `npx cap sync`) never set it.
   - Check both: a build without the flag must have no World 6 levels or Hallow's End book.
   - Check what else depends on 100 levels: `LEVELS` is `ALL_LEVELS.length`, the 5-20 ending shows the "coming soon" Hallow's End sneak peek (`openSoon` in `src/ui/screens.js`), the Endless Night tome, the shelf layout, and save migration in `src/save.js`.
3. **Never build or upload a store build from the World 6 branch.**

## How worlds are built (patterns to follow)

- **Levels are data.**
  - A world is `src/data/worlds/worldN.js`. Schema: `src/data/levels.js`; target shape: `docs/WORLDS.md` §9.
  - Copy the structure of `world5.js`: pacing, monster pool, graves, unlocks, the level-10 and level-20 bosses, hand-authored levels 11–19, a level-16 monster and a level-20 perk (`src/data/perks.js`).
  - No level-specific numbers in the engine.
- **Quests**: `src/data/questTable.js`, generated by `tools/quest_gen.mjs`. Hand edits are fine. Check every quest can be done with the level's monster count. The owner found impossible Fire/Ice and Grey pierce quests in Release 1.
- **Storybook shelf**: one book per world, with lore (`src/data/lore.js`) and a bestiary (`src/data/bestiary.js`). See `openLevels` / `openBook` in `src/ui/screens.js`.
- **Art**:
  - Toy Plastic style, drawn in code, rules in `docs/ART_BRIEF.md`.
  - Characters are one module per world in `src/engine/render/chars/`; check them with `tools/char_sheet.py`.
  - **Never paint or use `shadowBlur` per frame.** Bake into sprites. The owner's phone lagged from exactly this.
- **Balance**:
  - `tools/balance_bot.py`, 3 repeats per night minimum. Run it with `--offset 0` and `--offset -1` (`profile()` and `UNLOCK` cover levels up to 100, so extend them for 101–120).
  - Always test the build: `npm run build`, then `python3 tools/serve_dist.py`, then `--url http://127.0.0.1:4173/`.
  - Smoke test: `.venv/bin/python tools/smoke_test.py --url http://127.0.0.1:4173/`.
- **Docs**: rules change → `docs/GAME_DESIGN.md` changes in the same edit. Keep `WORLDS.md`, `LOOT.md` and `CLAUDE.md` in sync too.
